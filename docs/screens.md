# 画面・遷移

正常系のフローは要件定義書 3.6.3 / 10 章にある。
**本ドキュメントは異常系の遷移と、画面ごとの状態を定義する。**
実装で漏れるのは常に異常系。

---

## 1. 予約 LP（未認証）

### 正常系

```
LP-01 トップ
  ↓
LP-02 日付選択 ──→ LP-03 時間帯選択 ──→ LP-04 プラン選択
                                              ↓
LP-08 完了 ←── LP-07 決済 ←── LP-06 顧客情報 ←── LP-05 人数選択
```

Phase 0 は `NullPaymentProvider` のため LP-07 は素通りするが、
**画面と遷移は実装しておく**（Phase 1 で決済 UI を差し込むだけにする）。

### 異常系

| 発生箇所 | 状況 | 挙動 |
|---|---|---|
| LP-02〜05 | 選択中に満席化 | 次ステップへ進む時点で再検証。満席なら**その画面に留まり**、該当選択肢を無効化して通知 |
| LP-06 → 決済 | 在庫確保失敗 | LP-04 まで戻す。「選択された枠は満席になりました」 |
| LP-07 | 決済失敗 | LP-06 に戻す。**hold は維持**（TTL 内なら再試行可能） |
| LP-07 | 決済画面で離脱 | hold は TTL で自動解放。再訪時は最初から |
| LP-07 | hold が TTL 失効 | 「お時間が経過しました」→ LP-02 へ。**決済させない** |
| LP-07 | 決済成功したが在庫確保失敗 | LP-08 に「確認中」と表示。`needs_review` として店舗へ通知 |
| 全画面 | 予約受付期間外 | LP-01 に「現在オンライン予約を受け付けていません」 |
| 全画面 | 店舗が停止中 | LP-01 に案内のみ表示。予約導線を非表示 |

**LP-07 で hold 失効を検出したら、決済に進ませてはならない。**
決済後に枠がない状態は返金処理が必要になり、最も避けたい。

### hold の残り時間表示

LP-06 以降で**残り時間をカウントダウン表示**する。
無言で失効すると、入力内容を失った理由が伝わらない。

### LP-09 予約確認・変更・キャンセル

```
{slug}.book.omabo.jp/r/{management_token}
```

| 状況 | 挙動 |
|---|---|
| トークン無効 | 410。「リンクが無効です」＋店舗連絡先を表示 |
| 予約が `cancelled` | 予約内容を参照のみ表示。操作ボタンなし |
| 予約が `superseded` | **新予約へリダイレクト**（旧コードからも辿れる導線） |
| キャンセル期限超過 | キャンセルボタンを無効化。ポリシーと店舗連絡先を表示 |
| 変更で在庫不足 | その場でエラー。**旧予約は無傷**であることを明示 |
| 変更成功（金額変化あり） | 新予約コードを表示。**「予約番号が変わりました」を明示** |

**変更で予約コードが変わることを必ず伝える。**
顧客が古い番号を持ったまま来店するトラブルを防ぐ。

### ADM-01 ログイン

```
Email/Password 入力
  ↓
 [MFA 有効?]
  ├─ Yes → MFA コード入力 → ダッシュボード
  └─ No  → ダッシュボード
```

| 状況 | 挙動 |
|---|---|
| 認証失敗 | 「メールアドレスまたはパスワードが正しくありません」（どちらか特定させない） |
| 5 回失敗 | 15 分ロック。**失敗回数を画面に表示しない** |
| MFA 未設定の super_admin | MFA 登録画面へ強制遷移（スキップ不可） |
| セッション失効 | ログイン画面へ。**遷移前の URL を保持して復帰させる** |

### ADM-03 予約カレンダー

- 月/週/日ビュー
- チャネル別（`source_channel`）の色分け
- `needs_review` の予約は**明確に区別して表示**（バッジ + 色）

| 状況 | 挙動 |
|---|---|
| 該当日にスロット未生成 | 「未設定」と表示。エラーにしない |
| 席プラン未設定 | 空カレンダー + 「席プランを設定してください」への導線 |
| 大量データ | 表示範囲のみ取得。月ビューでも全予約を一括ロードしない |

### ADM-04 予約詳細

| 状況 | 挙動 |
|---|---|
| `superseded` な予約 | 「この予約は変更されました」＋新予約へのリンク |
| `previous_reservation_id` がある | 「変更前の予約を見る」リンク |
| `needs_review` | **理由を明示**（在庫競合 / 低信頼度 / プラン未解決）＋確定・却下ボタン |
| Staff が閲覧 | 設定により連絡先をマスク表示 |
| 返金が必要なキャンセル（Staff 操作） | キャンセルは成立、返金は「承認待ち」として admin へ |

### ADM-05 手動予約入力

| 状況 | 挙動 |
|---|---|
| 在庫不足 | **警告を表示した上で「それでも登録」を許可**（権限がある場合） |
| 在庫不足で権限なし | 登録不可。空き枠を提案 |
| `max_party_size` 超過 | 警告 + 強制登録可（電話予約を断れないため） |
| スロット未生成 | その場で生成して登録可能にする |

**LP と挙動が異なる点に注意。** 手動入力は「拒否できない予約」を扱う。

### ADM-18 要確認予約一覧

`needs_review` の予約を集約する画面。Phase 0 から必要。

| 理由 | 表示内容 | 操作 |
|---|---|---|
| `inventory_conflict` | 競合しているスロットの現況 | 確定（強制減算） / 却下 |
| `low_confidence`（Phase 1） | 解析結果と原文メール | 修正して確定 / 却下 |
| `plan_unresolved`（Phase 1） | プラン候補の一覧 | プランを選んで確定 / 却下 |

### ADM-06 席プラン設定

| 状況 | 挙動 |
|---|---|
| `inventory_type` を変更しようとした | **予約が 1 件でもあれば変更不可**。理由を明示 |
| 枠数を減らそうとした | 既存予約数を下回る値は拒否。現在の消費数を表示 |
| プランを無効化 | 既存予約がある将来スロットの一覧を表示して確認を求める |
| プール未設定 | 自動生成されたデフォルトプールを表示（編集可） |

### ADM-14 在庫管理

| 状況 | 挙動 |
|---|---|
| 売止設定 | 既存予約は維持される旨を明示 |
| `held` が存在するスロット | 「決済処理中 N 件」を表示（在庫が減って見える理由を示す） |
| スロット未生成の将来日 | 「未生成」と表示。手動生成ボタン |

**hold 中の枠を可視化すること。**
「予約が入っていないのに空きが減っている」という問い合わせを防ぐ。

## 4. 共通の異常系

| 状況 | 挙動 |
|---|---|
| ネットワークエラー | リトライボタン付きのエラー表示。**入力内容を保持** |
| 409 CONCURRENT_MODIFICATION | 「他のユーザーが更新しました」＋最新を再取得するボタン |
| 403 PERMISSION_DENIED | 「権限がありません」。機能の存在自体は隠さない |
| 429 RATE_LIMITED | 「しばらく時間をおいてください」＋残り秒数 |
| 500 | エラー ID を表示（サポート問い合わせ用）。詳細は出さない |

**入力フォームでエラーが発生した際、入力内容を消さない。**
特に LP-06（顧客情報）と ADM-05（手動予約）は入力量が多い。

## 5. i18n

- LP: **英語のみ**（Phase 0〜1）。ただし `next-intl` 等を最初から導入し、
  文字列をハードコードしない
- 管理画面: 日本語
- **メール**: `guest_language` に従う（Phase 0 は英語のみ）

日付・時刻の表示は**必ず店舗のタイムゾーン**で行う。
ブラウザのローカルタイムゾーンで表示しない（海外からの予約で日付がずれる）。
